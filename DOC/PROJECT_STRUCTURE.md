# Структура проекта 8AIV

Описание устройства программы: каталоги и файлы, модули и их функции, алгоритмы,
тактирование и потоки выполнения. Распиновка здесь не приводится: она есть
только в `Application/board/board_pins.h` и на схеме `DOC/SCH_8AIV.pdf`.

Прошивка модуля с 8 изолированными входами напряжения. Измерение выполняет один
АЦП `ADS8688` (16 бит, 8 каналов, внутренний источник опорного напряжения
4,096 В), подключённый к MCU через изолятор по SPI. Устройство работает как
Modbus TCP сервер, обнаруживается по протоколу PDP и обновляется через общий
загрузчик семейства.

## 3. Тактирование

| Параметр | Значение |
|---|---|
| Источник | внешний кварц 25 МГц (HSE), внутренний LSI включён для IWDG |
| PLL | M = 25, N = 320, P = 2, Q = 4 |
| SYSCLK = HCLK | 160 МГц (25 / 25 · 320 / 2) |
| APB1 (/4) | 40 МГц; таймеры на APB1 работают на удвоенной частоте 80 МГц |
| APB2 (/2) | 80 МГц |
| Задержка Flash | 5 тактов ожидания |
| Напряжение ядра | масштаб 1 |
| SPI АЦП | PCLK2 / 8 = 10,0 МГц, режим CPOL 0 / CPHA 1, кадры 16 бит |
| TIM2 (слоты сбора) | 80 МГц, ARR = 3124 (период 3125 тактов = 39,0625 мкс) |
| Таймбаза HAL | TIM1, счётчик 1 МГц, прерывание раз в 1 мс |
| Тик FreeRTOS | 1 кГц, кучи FreeRTOS 20 КБ |
| Тактирование MAC | 50 МГц RMII, приходит от коммутатора |
| IWDG | LSI / 64, перезагрузка 4095, около 8 с |

Частота 160 МГц выбрана ради SPI: при делителе 8 шина АЦП даёт ровно 10 МГц,
что является потолком для пути через изолятор.

## 4. Запуск и задачи

Порядок запуска (`Core/Src/main.c`):

1. `board_early_pins()` — первым оператором: линии шины АЦП переводятся в
   безопасное состояние (выбор выключен, тактовая линия в нуле).
2. `HAL_Init()`, `SystemClock_Config()`, `MX_GPIO_Init()`, `MX_IWDG_Init()`.
3. `ksz8863_boot_init()` — аппаратный сброс коммутатора только при холодном
   старте (включение питания или просадка). При мягком перезапуске коммутатор
   не трогается: он продолжает передавать транзитный трафик между внешними
   портами.
4. `osKernelInitialize()`, `MX_FREERTOS_Init()`, `osKernelStart()`.

Задачи FreeRTOS:

| Задача | Приоритет | Стек | Назначение |
|---|---|---|---|
| `defaultTask` → `app_run()` | normal | 512 Б | Инициализация и фоновый цикл раз в 100 мс. |
| `LED` | low | 256 Б | Тик 10 мс: главный индикатор и индикаторы каналов. |
| `AI` | high | 1536 Б | Запуск АЦП, каждые 2 мс обработка завершённых окон. |
| `ModbusSrv` | normal | 2048 Б | TCP-сервер Modbus. |
| `EthIf` | realtime | по настройкам LwIP | Приём кадров Ethernet. |
| `tcpip_thread` (LwIP) | 24 | 1024 слова | Сетевой стек. |
| `ethernet_link_thread` | | | Опрос состояния портов коммутатора раз в 100 мс. |

Прерывание TIM2 (приоритет 1) выше всех приоритетов, из которых разрешены
вызовы FreeRTOS, и сам вызовов RTOS не делает.

Порядок в `app_run()`:

1. Загрузка настроек (`settings_init`), при невалидных — значения по умолчанию.
2. Запуск задачи `LED` до проверки кнопки: иначе мигание сброса к заводским
   будет потеряно.
3. Если кнопка удерживается 2 с — `perform_factory_reset()`.
4. Запуск задачи `AI`.
5. `temp_module_init()`, `modbus_app_init()`, `apply_network_config()`,
   `ksz8863_ensure_rmii_port3()`, `modbus_tcp_server_start()`,
   `discovery_init()`.
6. Бесконечный цикл с периодом 100 мс (см. раздел 10).

## 5. Модуль `board` — шина АЦП

- `board_early_pins()` — безопасные уровни сигналов до остального кода.
- `board_spi_pins_af()` — передаёт линии шины периферии SPI после её настройки.
- `board_led_init()`, `board_led_set(ch, on)` — индикаторы каналов.
- `BOARD_ADC_MAP[8]` — соответствие входа AI0..AI7 каналу АЦП. Входы подключены
  не по порядку; только эта таблица знает соответствие, все остальные модули
  работают с номерами входов.
- `spi_init()` — SPI1 как ведущий, 16-бит, CPHA 1, PCLK2/8.
- `board_adc_frame(cmd)` — один кадр АЦП: выбор вниз, 16 бит команды, 16 бит
  данных, выбор вверх; возвращает `(первое полуслово << 16) | данные`. Данные
  кадра — результат преобразования канала, выбранного **в предыдущем** кадре
  (конвейер ADS8688).

## 6. Модуль `ads8688`

- Константы: команды (`NO_OP`, `RST`, `MAN_Ch_n`), доступ к регистрам
  (`ADS_REG_WRITE/READ`), извлечение байта из ответа (`ADS_REG_DATA`).
- `ads8688_init(range)` — команда RST, ожидание, установка диапазона всем
  восьми каналам и чтение обратно. До трёх попыток. Блокирующая, вызывается из
  потока до запуска сканирования.
- `ads8688_set_range(n, code)` — запись регистра диапазона и проверка чтением.

Линии сброса и выбора опорного напряжения на плате заданы аппаратно, поэтому
сброс выполняется программной командой, источник опорного напряжения —
внутренний.

## 7. Движок сбора `adc_scan`

### Идея

Один АЦП опрашивает 8 входов по кругу. Таймер TIM2 задаёт строгий ритм: каждый
слот (39,0625 мкс) в прерывании выполняется ровно один кадр АЦП. Данные
накапливаются по окнам, длина которых кратна периоду сети, поэтому наводка
50 и 60 Гц подавляется усреднением.

### Слот

В слоте `k` внутри окна выполняется `board_adc_frame(MAN_Ch((k+1) mod 8))`:
команда выбирает **следующий** канал, а принятые данные — результат канала
`k mod 8`. Полный круг занимает 8 слотов, то есть каждый вход измеряется раз в
312,5 мкс (3,2 кГц на вход). Время от выбора канала до его преобразования —
один слот, этого достаточно для установления сигнала.

### Окно

| Окно | Слотов | Длительность | Выборок на вход | Подавляет |
|---|---|---|---|---|
| длинное (по умолчанию) | 2560 | 100,000 мс | 320 | 50 и 60 Гц |
| короткое | 512 | 20,000 мс | 64 | 50 Гц |

Число слотов в окне кратно 8, поэтому у всех входов одинаковое число выборок.
В окне для каждого входа накапливаются: сумма кодов, сумма квадратов (для
оценки шума), минимум, максимум, число выборок на нижней и верхней границе
шкалы.

### Автомат прерывания

```
ST_RUN  --окно набрано--> публикация окна --> ST_RANGE
ST_RANGE: по одной записи регистра диапазона на слот (с проверкой чтением);
          затем одна проверка чтением регистра по кругу (самоконтроль);
          затем один пустой слот
ST_PRIME: два слота MAN_Ch(0), данные отбрасываются
ST_RUN  <--
```

- **Смена диапазона.** Поток вызывает `adc_scan_set_range(вход, код)`;
  прерывание применяет запись на ближайшей границе окна. Вместе с окном
  публикуется код диапазона, действовавший во время его набора, поэтому слой
  каналов точно знает, в каком диапазоне получены данные.
- **Самоконтроль.** На каждой границе читается обратно один из восьми
  регистров диапазона (по очереди). При несовпадении регистр перезаписывается,
  счётчик ошибок растёт, запись повторяется на следующей границе. Так
  обнаруживаются обрыв шины и потеря конфигурации АЦП.
- **Длина окна.** `adc_scan_set_window(20|100)` применяется на границе.
- **Стоимость.** Окно длится 2564 слота (2560 + служебные), то есть служебные
  слоты занимают около 0,16 % времени.
- **Нагрузка.** Прерывание занимает порядка 4 мкс из 39 мкс.

### Передача данных потоку

Завершённое окно записывается в один из двух буферов (по чётности номера) и
публикуется увеличением номера. `adc_scan_take()` копирует снимок и проверяет
согласованность: буфер окна `n` перезаписывается только окном `n+2`.

### Пауза на стирание Flash

`adc_scan_pause()` отключает таймер и прерывание, `adc_scan_resume()` снова
запускает сканирование с чистого окна. Вызывается вокруг стирания сектора, так
как стирание останавливает выборку команд из Flash на 1–4 с.

### Диагностика

`adc_scan_slots()` — число слотов, `adc_scan_overruns()` — сколько раз
обработчик не уложился в слот, `adc_scan_range_errors()` — несовпадения
регистров диапазона.

## 8. Модуль `ai` — каналы и математика

### Типы (`ai_types.h`)

- Режимы канала: 0 OFF, 1 «0–10 В», 2 «2–10 В» (живой ноль), 3 «0–5 В»,
  4 «±10 В», 5 «±5 В».
- Диапазоны АЦП: ±10,24 В, ±5,12 В, 0…10,24 В, 0…5,12 В (в 2,5 и 1,25 раза
  больше опорного напряжения).
- Биты статуса канала: NO_DATA, OVERRANGE, UNDERRANGE, WIRE_BREAK, ADC_CLIP,
  CONFIG_ERR, ADC_FAIL, OFF.
- `ai_ch_cfg_t` (хранится во Flash): калибровка (усиление, смещение),
  масштаб (нижнее и верхнее значение), режим, постоянная времени фильтра.
- `ai_model_t` и `ai_diag_t` — сервисные параметры входной цепи и порогов
  диагностики.

### Математика (`ai_math.c`)

Цепочка пересчёта среднего кода окна в напряжение на клемме:

1. **Код → напряжение на входе АЦП.** Для однополярных диапазонов
   `V = code · FS / 65536`, для двуполярных `V = (code − 32768) · FS / 32768`.
2. **Напряжение на входе АЦП → узел после делителя.** Учитывается входное
   сопротивление АЦП, подтянутое к смещению диапазона `V_B` (функции `aim_vn`,
   `aim_vp_from_vn`).
3. **Узел → клемма.** Метод узловых потенциалов для делителя с учётом тока
   нагрузки АЦП (`aim_vin`, обратная — `aim_vn_from_vin`). Номинальный
   коэффициент передачи цепи около 0,9898.
4. **Калибровка.** `V = gain · V_in + offset`.
5. **Масштабирование.** Линейное отображение сигнального диапазона режима в
   инженерные единицы (при равных нижнем и верхнем значениях — вольты).

Статус вычисляется так: насыщение на границе шкалы у половины выборок даёт
ADC_CLIP с OVERRANGE (и UNDERRANGE для двуполярных диапазонов);
превышение порога напряжения — OVERRANGE; для режима «2–10 В» напряжение
ниже порога — WIRE_BREAK, значение при этом NaN.

Дополнительно: значения по умолчанию, проверка допустимости (`aim_*_valid`).

### Слой каналов (`ai.c`)

- `ai_init()` — вызывается задачей `AI`: инициализация индикаторов и SPI,
  ожидание 500 мс после старта (питание изолированной части), `ads8688_init`,
  установка индивидуальных диапазонов, запуск `adc_scan_start`. Если АЦП не
  ответил, `ai_poll()` повторяет попытку раз в секунду.
- `ai_poll()` — каждые 2 мс: при наличии нового окна вызывает
  `process_window()`.
- `process_window()` для каждого канала: проверяет, что окно набрано в
  ожидаемом диапазоне (иначе состояние SETTLE), вычисляет среднее, минимум,
  максимум и шум (СКО в единицах кода), вызывает `aim_eval`, применяет
  экспоненциальный фильтр (`alpha = окно / (tau + окно)`), добавляет
  ADC_FAIL, если недавно были ошибки диапазона (удержание 50 окон), либо
  CONFIG_ERR.
- `ai_set_config`, `ai_get_config`, `ai_set_common`, `ai_get_common` —
  применение настроек из Modbus. Смена диапазона уходит в движок сбора, канал
  переходит в SETTLE до первого окна с новым диапазоном.
- `ai_command` — RESTART (сброс фильтра, ожидание нового окна) и APPLY
  (перечитать всё из настроек).
- `ai_get`, `ai_get_stats`, `ai_get_int16` — потокобезопасные снимки данных для
  Modbus (критические секции).
- `ai_module_flags` — флаги модуля: сбой АЦП, ошибка конфигурации, сканирование
  идёт, ошибка регистра диапазона, переполнение слота.
- `ai_led_tick` — индикаторы каналов: горит — данные есть, медленное мигание —
  данных ещё нет, быстрое — неисправность, погашен — канал выключен.

Состояния канала: OFF, SETTLE, RUN, ADC_FAIL.

## 9. Modbus

### Сервер (`modbus_tcp_server.c`)

- До 4 клиентов одной задачей, опрос по кругу. При заполнении слотов новое
  подключение вытесняет клиента, дольше всех молчавшего.
- Молчащий клиент отключается через 30 с; включён keep-alive (первая проба
  через 10 с, затем каждые 2 с, три пробы).
- Слоты закрываются принудительным сбросом соединения (RST), а не штатным
  закрытием: иначе при исчезновении клиента сокет надолго остаётся в
  состоянии ожидания и исчерпывает пул.
- Клиенты отсекаются при потере связи, подтверждённой с задержкой.
- Запрос засчитывается в статистику, только если сформирован ответ.

### Карта (`modbus_app.c/.h`)

Полная таблица регистров находится в комментарии `modbus_app.h`; кратко:

| Область | Регистры |
|---|---|
| Holding 0–23 | показание (мВ, только чтение), режим, фильтр |
| Holding 24–87 | float32 ×8: усиление, смещение, масштаб low, масштаб high |
| Holding 101–119, 130, 131 | сетевые параметры, режим LED, триггеры, команда канала |
| Holding 132–154 | окно усреднения, модель входной цепи, пороги диагностики |
| Input 300–411 | значение, raw (В), статус, счётчик, средний/мин/макс код, шум, насыщение, состояние |
| Input 120–134 | версия, uptime, ID модуля, температура, флаги, число окон, переполнения |

Значения float32 передаются двумя регистрами, старшее слово первым.
Многоканальные величины сгруппированы по величине: 8 подряд идущих регистров
(или пар) — каналы AI0…AI7.

### Алгоритм записи

1. `backup_analog()` — копия аналоговой части настроек.
2. `apply_holding_write()` — запись в настройки; запись половины float по FC06
   ожидает вторую половину.
3. `commit_analog()` — проверка и передача согласованных блоков в слой каналов.
   Для FC16 несогласованный блок отклоняет весь запрос (исключение 3), для FC06
   откат не требуется до прихода второй половины.
4. При ошибке `restore_analog()` возвращает прежние значения.

Триггеры (сохранение, перезагрузка, переход в загрузчик, сброс коммутатора,
сброс к заводским) только взводят флаги; сами действия выполняет фоновый цикл,
чтобы Flash и сброс не выполнялись в потоке стека LwIP.

## 10. Фоновый цикл (`app_run`, 100 мс)

- обновление индикации по трафику Modbus и состоянию линии;
- сохранение настроек по триггеру Modbus или PDP;
- сброс к заводским по триггеру (сначала запись Flash, затем 3,5 с индикации,
  затем перезагрузка);
- запрос сброса коммутатора (флаг для потока опроса линии);
- переход в загрузчик: запись магического слова в зарезервированную ячейку RAM
  и перезагрузка, загрузчик читает и сбрасывает флаг;
- перезагрузка по триггеру;
- обновление сторожевого таймера.

Сохранение настроек (`save_settings`): `modbus_app_sanitize_staged()` заменяет
несогласованные блоки действующими, затем `settings_save()`.

## 11. Настройки и Flash

- `settings_t` расположена в секторе настроек Flash, защищена CRC32, имеет
  магическое число и версию; структура не содержит заполнителей, порядок и
  размер полей нельзя менять без повышения версии.
- `settings_init()`: при неверных магии, версии или CRC применяются значения по
  умолчанию. Чистый (стёртый) сектор — заводское состояние, а повреждённая
  запись выставляет ошибку конфигурации.
- `settings_save()` вызывает `flash_ram_write_sector()` и ведёт счётчик
  успешных сохранений и результат последнего (регистры сохранения).
- `flash_ram_write_sector()`: приостанавливает сканирование, входит в
  критическую секцию FreeRTOS, стирает и программирует сектор функцией из RAM
  (HAL здесь не годится: стирание останавливает прерывание его таймбазы),
  разблокирует и блокирует управляющий регистр, сбрасывает кэш данных, сверяет
  записанное, возобновляет сканирование.
- Функция стирания компонуется в секцию `.RamFunc`, которая копируется в RAM при
  старте; файл собирается с `-fno-builtin -fno-jump-tables`, чтобы
  компилятор не вставлял вызовы библиотеки и таблицы переходов во Flash.

## 12. Сеть

- **Адресация** (`apply_network_config`): статический адрес, DHCP или
  детерминированный link-local из `net_id`. Применяется при старте и «на лету»
  после изменения настроек (через `tcpip_callback`).
- **Идентичность** (`net_id`): MAC и link-local адрес считаются из 96-битного
  уникального ID микроконтроллера, поэтому прикладная прошивка и загрузчик
  показывают одинаковые значения без хранимых данных.
- **PDP** (`discovery`): UDP, широковещательные запросы и ответы. Операции:
  опрос (IDENTIFY), смена сети, смена имени, мигание индикатором,
  перезагрузка, сброс к заводским. Запрос исполняется, если целевой MAC нулевой
  или равен собственному. Ответ IDENTIFY имеет фиксированный размер.
- **Проверка адреса** (`addr_probe`): перед применением нового адреса по PDP
  отправляются три ARP-пробы; если адрес занят, смена не выполняется и
  отправителю сообщается отказ. Приёмный путь обязан передавать каждый кадр в
  `addr_probe_input()` до стека LwIP.
- **Коммутатор** (`ksz8863`): драйвер шины управления, политика сброса,
  аварийное восстановление при отсутствии ответа около 5 с. Весь доступ к
  шине управления идёт из потока опроса линии.
- **Опрос линии** (`ethernet_link_thread`): раз в 100 мс читает состояние
  внешних портов; признак «связь устойчива» учитывает задержку 2 с, так как
  порт коммутатора кратковременно теряет связь после подключения кабеля.

## 13. Индикация и кнопка

- Главный индикатор (`led_module`) имеет режимы «всегда выкл», «всегда вкл» и
  автомат состояний: нет опроса (одна короткая вспышка каждые 3 с), идёт опрос
  (две вспышки каждые 1,5 с), нет связи (три вспышки каждые 3 с), сброс к
  заводским (непрерывное мигание до перезагрузки, приоритетнее остальных
  состояний).
- Индикаторы каналов управляются слоем `ai`.
- Кнопка (`button_module`): удержание при старте 2 с запускает сброс к
  заводским; сторожевой таймер при ожидании обновляется.

## 14. Температура кристалла

`temp_module` работает с АЦП1 напрямую через регистры (HAL ADC в проект не
входит): одиночное программное преобразование внутреннего датчика, пересчёт по
калибровочным значениям кристалла в десятые доли градуса. Результат доступен
по Modbus (регистр 126 и дублирующий holding 130).

## 15. Взаимодействие с загрузчиком

- Образ размещается с начала области приложения, заголовок `fw_header_t`
  находится по смещению `0x200` и содержит идентификатор продукта, ревизию
  платы, версию и вспомогательные поля.
- Последние 16 байт RAM зарезервированы под ячейку запроса загрузчика.
- Загрузчик принимает образ, если идентификатор продукта совпадает точно, а
  старший байт ревизии платы совпадает.
- Прошивка только по SWD без записи метаданных оставляет плату в загрузчике;
  используется OTA или скрипт загрузчика `service_flash.ps1`.
- Версия прошивки определяется единственной константой в `fw_header.h`; из неё
  же берутся регистры версии.

## 16. Сборка и проверка

- Сборка: `cmake --preset Debug`, затем `cmake --build --preset Debug`
  (аналогично `Release`). Выходные файлы `.elf`, `.hex`, `.bin`, `.map` — в
  `build/<пресет>/`.
- Host-тесты математики: нативный `gcc`, цель `test_ai`. Проверяются диапазоны,
  преобразования кода, обращаемость модели входной цепи, статусы, калибровка,
  масштабирование и проверки допустимости.
- Движок сбора содержит код уровня регистров и проверяется только на плате:
  тайминги SPI, загрузка прерывания, самоконтроль регистров диапазона.
